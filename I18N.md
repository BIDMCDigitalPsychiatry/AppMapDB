## Interface translation (English / French / German)

The site interface is available in English (default), French and German.
- **Choosing a language:** the language selector (🌐 EN/FR/DE) is in the top bar, the mobile menu and
  the PWA bar. The choice is saved in the browser.
- **Shareable links:** `?lang=fr` / `?lang=de` / `?lang=en` open a link in that language.

**Not translated:** app names, store descriptions, rater reviews, news posts, comments, team bios and any
other database content. On app detail pages, the store's *own* description in French or German is shown
when the store has one, with a note when only English exists.

### How it works
| Piece | Location |
|---|---|
| Helpers: `useT()`, `tx()`, `tc()`, `<T>` | `src/i18n/index.tsx` |
| Language selector | `src/i18n/LanguageSelector.tsx` |
| MUI component text and date-picker locale | `src/i18n/LocalizedMui.tsx` |
| Catalogs (lazy-loaded, so English visitors download nothing extra) | `src/locales/fr.json`, `src/locales/de.json` |
| Every string, plus the files that use it (context for translators) | `src/locales/source.json` (generated) |
| Terminology and style rules | `src/locales/GLOSSARY.md` |
| Extraction / check tool | `scripts/i18n/extract.js` |
| Tests (catalogs complete, placeholders kept, extractor sane) | `src/i18n/catalog.test.ts` |

- **The English text is the key.** `t('Save')` looks up `"Save"` in the catalog. Missing translations fall
  back to English, so nothing breaks.
- **Stored data stays English.** Taxonomy values, saved filters, statuses, role keys, dialog ids and route
  paths keep their English values; only what's displayed is translated (`t(value)`). Search also matches
  translated tag names when French or German is selected.
- **Shared components translate their own string props.** These include the field components' labels,
  tooltips and errors; dialog titles and buttons; tab labels; and snackbar messages.
- **Dates follow the interface language.** `getDayTimeFromTimestamp` and `formatWithDefault` in `src/helpers.tsx`
  read it automatically.

### Adding or changing interface text
1. Wrap new text:
   - `t('Some text')` in components;
   - `t('Viewing {{count}} apps', { count })` for values. Never concatenate translated fragments.
2. For module-level constants, mark the text with `tx('…')` and call `t(value)` where it's displayed.
3. If the same English word has two meanings, use `tc('context', 'Word')`. Examples:
   - `tc('apa', 'Accessibility')` is the framework category;
   - plain `'Accessibility'` is the feature chip.
4. Run `npm run i18n:extract`. It regenerates `source.json` and lists missing French/German entries.
5. Add those entries to `fr.json` and `de.json`, following `GLOSSARY.md`.
6. `npm test` fails until every string has both translations and keeps its `{{placeholders}}`.
7. Editing the English text changes the key. Move its translations to the new key, then run
   `node scripts/i18n/extract.js --prune` to drop unused entries.

### How the current translations were produced (Oct 2026)
1. 1,523 strings were drafted in batches with a shared glossary.
2. Each batch got an independent review by a second model (Fable), which made about 200 corrections.
3. A consistency pass across the full catalogs made 95 terminology fixes.
4. A ChatGPT cross-check is optional.
5. French and German speakers on the team review the result once it's live.

**Known follow-ups:**
- The search assistant's crisis message shows the US crisis line. French and German users need a local number.
- The survey's self-efficacy items use the validated German wording. The French and System Usability Scale
  items should be swapped for their official validated versions if the survey data is used for research.
